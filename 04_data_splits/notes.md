# 04｜训练、验证与测试

## 核心概念

训练集参与权重更新；验证集用于选方案；测试集只在最后评价。先按文档划分再切片，可减少相邻片段泄漏。

## 观察一个例子

同一篇文章的两段分别进入训练和测试会虚高测试成绩。假设把同一篇教程切成 A、B 两段，A 用来训练、B 用来测试。模型可能凭前半篇的措辞猜出后半篇；改为按整篇文档分组后，再看测试分数是否下降。

## 技术细节与实践流程

### 技术机制

数据划分的单位应尽量对应独立来源，例如整篇文档、同一对话或同一作者的相关记录，再在各集合内部切块。训练集用于更新参数，验证集用于开发和选择版本，封存测试集用于最终检查。精确哈希只能发现完全相同的内容；改标题、改标点或局部转载还需要近重复检查。

### 实践步骤

先为文档分配稳定 ID 和来源字段，再生成 train、validation、test 三份清单。检查 ID 与规范化文本哈希是否相交，之后抽检近重复。demo 验证三组示例的哈希不相交；可以加入一条相同文档，观察断言失败，理解泄漏检查的作用。

### 检查与常见错误

先切片再随机划分，可能把同一文章的上下段放入不同集合。反复查看封存题并据此改数据，会使它成为开发集；此时应保留历史结果，并准备新的最终测试，而不是继续称它为未见评估。

## 自问自答

**问：为什么测试集不能反复调参？**

答：反复看测试反馈会把它变成事实上的验证集。
