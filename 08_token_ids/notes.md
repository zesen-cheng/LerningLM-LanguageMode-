# 08｜文本如何变成 token ID

## 核心概念

tokenizer 定义把文本切成 token 并映射到整数 ID 的规则。token 不必是汉字或单词；不同切分会改变长度与训练成本。

## 观察一个例子

同一句中文在两个 tokenizer 下可能得到不同 token 数。把“机器学习”交给两个假设的切分器：一个切为四个单字，另一个切为“机器/学习”。再映射成 ID，就得到长度 4 与长度 2 的序列；切分方案会影响训练长度。

## 技术细节与实践流程

### 技术机制

编码流水线通常包括文本规范化、预切分、子词匹配或合并、ID 映射和特殊标记处理；解码执行对应的还原。BPE 的训练学习常见片段的合并规则，运行时使用固定规则，并不在每次请求中重新训练。token ID 是类别索引：ID 100 不比 ID 10“更有意义”，数值大小不能当语义距离。

### 实践步骤

demo 用字符词表编码再解码，先核对文本是否一致，再打印每个字符的 ID。扩展练习可改成“机器/学习”这种子词切分，比较同一文本的序列长度。真实 tokenizer 的各阶段可以参考 [Tokenizers 编码流水线](https://huggingface.co/docs/tokenizers/pipeline)，但本课字符演示不是完整 BPE。

### 检查与常见错误

回编码应与所选规范化策略一致：如果策略会改大小写或空白，就不能同时要求逐字节还原原文。ByteLevel 中一个 token 也可能只覆盖部分 UTF-8 字节，单独查看一个 ID 的解码字符不一定完整；应同时检查整段编码和解码。

## 自问自答

**问：token 与 tokenizer 的区别？**

答：token 是切分后的单位；tokenizer 是切分与编码/解码规则。
