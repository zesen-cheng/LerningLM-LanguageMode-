# 09｜Embedding 与位置

## 核心概念

token ID 只是索引；embedding 表把索引映射成可训练向量。位置编码或位置机制让模型区分先后顺序。

## 观察一个例子

“猫追狗”和“狗追猫”用到类似字，却不能忽略顺序。先给“猫”“追”“狗”各取一个 ID，再查表得到向量。若交换“猫”“狗”的位置，ID 集合没变，但位置顺序改变；模型应据此区分谁追谁。

## 技术细节与实践流程

### 技术机制

设词表大小为 V、隐藏维度为 D，embedding 是形状 `[V,D]` 的可训练表。输入 ID 形状 `[B,T]`，查表后得到 `[B,T,D]`。位置机制告诉模型顺序；demo 使用向量相加来说明这一点，而本案例用 RoPE 旋转 Q/K 的特征，并不是把同一位置向量直接加到 embedding 上。

### 实践步骤

运行 demo，交换“猫”和“狗”的顺序，观察位置表示与 token 表示共同变化。再按 V=32768、D=768 计算 embedding 元素数为 25,165,824。若输入与输出词表层共享权重，这张表只计一次参数，但不会因此省掉整个模型的激活或注意力开销。

### 检查与常见错误

词表改变会改变 ID 的语义，需要同步 embedding 与输出层；仅保证矩阵尺寸相同仍不够。位置机制支持某种长度也不代表长上下文能力已经训练好，超过训练分布的长度应另做评估。

## 自问自答

**问：embedding 是检索向量数据库吗？**

答：这里指模型内部的 token 向量；检索 embedding 是另一种用途。
