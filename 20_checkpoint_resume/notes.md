# 20｜检查点与恢复

## 核心概念

checkpoint 应保存模型、优化器、调度器、随机状态、step 和数据位置；只存权重通常不能精确恢复训练轨迹。

## 观察一个例子

中断后从最近一个已完整写入的检查点恢复。在第 100 步保存完整状态，第 101 步前模拟中断。重新启动时核对恢复的 step、优化器和数据位置，观察下一批是否与预期一致，而不只看文件能否打开。

## 技术细节与实践流程

### 技术机制

可恢复检查点应包含模型权重、优化器状态、更新步数、配置和数据位置；需要精确恢复时，还应保存调度器、随机状态及混合精度缩放状态。模型 `state_dict` 只解决权重恢复。可先写临时文件，再校验并替换正式文件，保留上一份已知完整版本；完整性还需通过实际加载和续跑确认。

### 实践步骤

demo 保存和读取一个 JSON 状态，是恢复字段的示意。正式实验在固定步数停下，核对恢复后的学习率、优化器统计、下一批 ID 和下一次更新。连续运行与中断运行分别记录相同位置的 loss 或权重差异。训练状态保存的基本结构见 [PyTorch 检查点教程](https://docs.pytorch.org/tutorials/recipes/recipes/saving_and_loading_a_general_checkpoint.html)。

### 检查与常见错误

能够打开文件不等于轨迹一致。本案例保存了采样位置并重建顺序，但未保存全部随机状态，因此只能据已验证内容描述恢复能力。只加载可信检查点，尤其不要未经检查加载可能执行反序列化代码的陌生文件。

## 自问自答

**问：为什么先写临时文件再替换？**

答：避免中断产生半写入的损坏文件。
