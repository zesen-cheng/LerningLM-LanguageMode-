# 22｜基础模型评估

## 核心概念

固定验证集计算损失或困惑度，并用固定提示、解码参数做生成测试。检查语言连贯、重复、乱码和未见主题，保存原始输出。

## 观察一个例子

低验证损失但对话混乱，提示模型学到续写但未学会遵循角色。准备十条从未参与训练的固定提示，对两个检查点使用同样的温度与最大输出长度。除损失外，逐条标注重复、乱码、语言切换和续写偏差。

## 技术细节与实践流程

### 技术机制

基础评估先在固定验证文本上累计所有有效 token 的负对数概率，再除以有效 token 数。使用自然对数时 `PPL=exp(平均NLL)`；只有 tokenizer、数据分布、长度处理和掩码一致，困惑度才便于比较。不同词表切出的 token 单位不同，不能直接用 PPL 判断哪个模型绝对更好。

### 实践步骤

demo 用平滑 bigram 计算未见句子的 NLL，是基础评估原理的示意。完整模型评估先切换 eval 模式并关闭梯度，固定验证块；再用固定提示测试中文连贯、重复、乱码、事实、算术和格式。记录模型版本、采样参数与原始输出，分别报告预测指标和行为结果。

### 检查与常见错误

不要把训练 loss 当验证 loss，也不要把最新日志里的验证值误认成当前 step 刚评估的值。若生成测试使用随机采样，可记录多个种子的波动。PPL 降低支持语言建模目标改善，但不能单独证明正常多轮聊天或知识正确性。

## 自问自答

**问：为什么要封存评估提示？**

答：避免反复针对同一组提示调参后虚高成绩。
