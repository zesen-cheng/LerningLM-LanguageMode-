# 24｜对话样本与损失掩码

## 核心概念

SFT 样本需要明确系统、用户、助手的边界。常见做法只对助手回答计算损失，避免把用户文本当目标回答。

## 观察一个例子

多轮样本保留前文，但目标位置只覆盖助手输出。构造“用户：你好／助手：你好！”的样本，把用户部分标签设为不计损失，仅在“你好！”位置优化。打印掩码，确认模型没有被训练去生成用户自己的话。

## 技术细节与实践流程

### 技术机制

SFT 的 input_ids 包含系统、用户和助手上下文，labels 只在需要监督的目标位置保留 token ID，其余常设为 -100。attention_mask 决定哪些输入位置可参与计算，loss mask 决定哪些目标计入损失，两者不是一回事。用户文本虽不直接计损失，仍可为助手预测提供条件。

### 实践步骤

先渲染完整多轮模板，再编码并标出每段来源，检查移位后的 logits 与目标对应关系。demo 只对助手回复和 EOS 两个位置计损失；真实实现还要验证截断后监督位置仍存在，以及 padding 被排除。使用 TRL 时可参考 [助手消息监督说明](https://huggingface.co/docs/trl/sft_trainer#train-on-assistant-messages-only)，模板必须能正确产生助手位置掩码。

### 检查与常见错误

不要按中文字符偏移直接推断 token 下标，也不要让两处代码重复执行标签移位。长对话截断可能只留下用户提示而没有答案；这类全掩码样本应识别并处理。结束 token 的监督与推理停止配置也应一致。

## 自问自答

**问：模板为何必须与推理一致？**

答：边界 token 不一致会让模型不知道何时回答或停止。
