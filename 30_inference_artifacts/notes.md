# 30｜推理模型文件

## 核心概念

部署通常需要模型结构配置、权重、tokenizer、特殊 token 和生成模板；缺一个都可能得到错误输出。量化改变权重表示以节省资源。

## 观察一个例子

只复制权重却用错 tokenizer，token ID 语义会错位。将模型权重、结构配置、tokenizer 和结束 token 放进同一推理目录。若故意换成不匹配的 tokenizer，观察输出异常；再恢复配套文件核对。

## 技术细节与实践流程

### 技术机制

推理包需同时包含权重、结构配置、tokenizer、特殊 ID、模板与生成默认值。FP16/BF16 权重每元素约 2 字节，INT8 约 1 字节，INT4 原始值约半字节，但量化还需缩放因子等元数据；量化权重、激活和 KV cache 是不同选择。INT8/INT4 不是“小数位少一点的 FP16”，通常需要分组或逐通道映射与对应算子。

### 实践步骤

demo 检查几个模拟工件存在，不会转换真实模型。交付时先在原生实现中加载，核对形状、哈希、结束标记和固定提示，再讨论适配框架。[Ollama](https://docs.ollama.com/) 可用于运行与管理模型，[vLLM](https://github.com/vllm-project/vllm) 与 [SGLang](https://docs.sglang.io/) 提供推理服务能力；自定义架构和文件格式必须逐项确认支持，不能仅重命名文件导入。

### 检查与常见错误

量化需在同一评估集上比较误差、输出与实际资源开销，不保证免费提速。本案例 GQA 的未展开 KV 理论存储随 `2×层数×batch×长度×KV头数×头维度×每元素字节` 增长；实际实现是否展开、缓存以及运行时布局会影响显存，不能把这个估式当实测。
