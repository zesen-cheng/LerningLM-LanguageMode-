# 31｜HTTP/JSON 最小接口

## 核心概念

服务把请求解析为输入、调用推理并返回结构化 JSON。接口应限制输入长度、并发、超时与错误响应。

## 观察一个例子

POST /generate 接收 prompt 和 max_tokens，返回 text 与耗时。向本地接口发送包含 prompt 与 max_tokens 的 JSON，请求成功时返回文本与状态码。再分别发送空提示、过长提示，核对错误码与超时行为是否稳定。

## 技术细节与实践流程

### 技术机制

HTTP 处理链应把输入解析、参数验证、模型调用和输出序列化分开。请求明确 prompt 或 messages、最大新 token 数与允许的采样设置；响应包含文本、模型版本、停止原因与 request_id。客户端错误和服务异常应使用稳定错误结构，服务器日志保留详细诊断，但不把内部路径或凭据返给客户端。

### 实践步骤

demo 在内存里模拟 POST /generate，并不监听端口。真实实现先只绑定本机，检查字符串类型、请求大小、编码后长度和参数范围，再调用模型。分别测试正常、空输入、超长、未知模型与后端未就绪；请求超时或取消后应释放任务资源，而不只停止前端显示。

### 检查与常见错误

输入字符数不能替代 token 长度，必须确保输入加输出预算不超过上下文限制。输出字段中的 text 还要定义是全文还是仅新增文本。用户提交的文件名或路径不能直接成为服务器读写目标；接口不应扩大为任意文件或命令执行入口。
