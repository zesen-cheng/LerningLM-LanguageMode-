# 32｜流式输出与 SSE

## 核心概念

SSE 把逐段生成结果写成事件流，客户端无需等完整回复。需要明确完成标记、断线处理与错误事件。

## 观察一个例子

模型每生成一段就发送一个 data 事件，最后发送结束事件。让模型生成三个片段，服务端依次发出三条 SSE data 事件，最后发完成事件。客户端边收边显示；中途断开时检查是否能正确结束而不是无限等待。

## 技术细节与实践流程

### 技术机制

SSE 使用 UTF-8 文本事件流，响应类型为 text/event-stream，事件通常以空行分隔，可包含 event、data 和 id 字段。每个片段的 data 可以是 JSON，但一次网络读取不保证正好包含一个完整事件。最终完成与错误也要定义事件语义，SSE 标准本身不规定模型的 delta 字段或结束标记。参见 [MDN SSE 说明](https://developer.mozilla.org/en-US/docs/Web/API/Server-sent_events/Using_server-sent_events)。

### 实践步骤

demo 拼接并解析完整的三个教学事件，没有真实网络传输。进一步测试把同一事件拆成多个网络片段，以及把多个事件放进一个片段：客户端应先缓冲到完整事件再解析。服务端输出后及时刷新，网关不能无限缓冲；记录首片段延迟和总耗时，并在完成、错误或取消时停止接收。

### 检查与常见错误

字节流可能在中文字符中间分段，需要增量 UTF-8 解码；不能逐个网络包直接当 JSON。浏览器原生 EventSource 与带请求体的 fetch 流式调用也不是同一种请求方式。断线重试不自动等于从模型中断处继续，恢复协议需单独设计。
