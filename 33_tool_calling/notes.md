# 33｜结构化输出与工具调用

## 核心概念

function calling 通常由模型提出工具名和参数，应用验证参数并执行，再把结果传回模型；模型本身不因输出 JSON 就自动执行工具。

## 观察一个例子

查天气先产出 city 参数，程序调用天气源后把结果交给模型回答。用户问天气时，模型先给出工具名和城市参数，程序核验城市后才调用天气源。若参数缺失，程序返回结构化错误，模型再根据错误向用户澄清。

## 技术细节与实践流程

### 技术机制

工具调用分为模型提出请求、宿主验证、执行工具、回传结果和模型继续回答。结构包含工具名、参数和关联 ID；参数 schema 约束类型与必填字段，但还要做业务范围检查。输出合法 JSON 只是语法检查通过，不能证明工具存在、参数真实或该操作获得授权。

### 实践步骤

demo 仅允许 add 工具，并检查两个整数后返回 5。扩展时添加缺少参数、未知工具和类型错误的测试，确认不合法请求不会执行。真实工具设置超时和输出大小限制，回传结构化成功或失败；多次工具请求保留 call_id，避免把结果配给错误的一轮。

### 检查与常见错误

不能把模型输出传给 eval、shell 或不受限的文件访问。对有外部副作用的工具，应由宿主判断权限与确认要求；重试还要防止重复执行。工具返回的文本也是外部数据，不能自动当成更高权限指令。

## 自问自答

**问：谁执行外部操作？**

答：宿主程序或网关，不是模型权重本身。
