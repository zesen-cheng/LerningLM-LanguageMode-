# 35｜网关与可观察性

## 核心概念

网关负责鉴权、限流、路由、超时、日志与最小化暴露。训练进度页面与推理 API 是不同服务，宜分离权限。

## 观察一个例子

只向本机绑定服务与向公网开放服务有不同威胁面。给同一服务配置本机访问与受控远程访问两种入口，记录鉴权失败、限流和超时响应。对比后确认训练状态页面与模型推理接口没有共用不必要的权限。

## 技术细节与实践流程

### 技术机制

网关在模型前处理身份、额度、模型路由、超时与可观察性。鉴权回答“是谁”，授权回答“能做什么”；限流控制请求频率，并发限制控制同时占用后端的任务数量。训练进度读取与推理请求应分离权限，日志用 request_id 关联阶段，默认不记录完整私密输入或访问密钥。

### 实践步骤

demo 模拟未知密钥返回 401、额度用完返回 429，没有真实鉴权部署。实际本地服务先限制监听范围，密钥放受控配置或环境变量，不提交仓库；远程访问还需受控入口与传输保护。分别验证无凭据、错误凭据、权限不足、限流和后端超时，并确认面板不会暴露权重或任意文件。

### 检查与常见错误

CORS 不是身份认证，隐藏网址也不是访问控制。127.0.0.1 只指向发起访问的设备；手机上的同一地址不会指向电脑。浏览器取消请求后，网关需传递取消信号，避免生成任务继续占用显存。

## 自问自答

**问：日志应该存完整用户输入吗？**

答：默认尽量最小化并设置保留期限。
