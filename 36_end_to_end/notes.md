# 36｜端到端联调

## 核心概念

从客户端请求到 tokenizer、推理、流式传输、网关和错误路径逐项测试。交付时固定模型版本、依赖和启动命令。

## 观察一个例子

同时测试正常问答、超长输入、断线和模型未就绪。从客户端发“你好”，依次记录网关、推理服务和模型的版本及耗时；再模拟模型尚未加载。正常与异常两条链都能复现，才算联调完成。

## 技术细节与实践流程

### 技术机制

端到端链路不仅是模型前向，还包括客户端序列化、网关验证与排队、模板渲染、tokenizer 编码、推理、解码和响应传输。用同一 request_id 记录各阶段起止时间，才能区分加载、排队、首 token 和完整输出耗时。健康检查也要区分进程活着与模型已经加载可用。

### 实践步骤

demo 把请求路由到确定性的模拟后端，不实际加载权重。真实联调先做非流式最小请求，再验证流式拼接相同；随后测试超长输入、未知模型、后端未就绪、取消和超时。每次记录模型、tokenizer、模板和代码版本，确认返回的是预期后端而非旧进程或 mock。

### 检查与常见错误

HTTP 200 只代表某种接口成功，不能证明请求经过真实模型；固定回答也可能来自缓存或模拟。最终验收既要检查协议，又要检查未见输入的生成内容。只测试正常路径会遗漏资源泄漏与错误状态，异常联调不可省略。
