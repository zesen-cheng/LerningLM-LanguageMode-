# 37｜案例：设备、配置与目标

## 核心概念

本地案例目标是训练约 0.2B 参数的中文基础模型，再探索对话 SFT。先读真实配置和日志，不把课程示意数当成最终成绩。

## 观察一个例子

配置含词表 32768、上下文长度 1024，二者不是同一量。读本案例配置中的 vocab_size=32768 和 block_size=1024，分别写下“可用 ID 种类”和“单次序列长度”。再对照模型参数统计，避免把三个数字都叫规模。

## 技术细节与实践流程

### 技术机制

本案例可核验结构为 195,075,840 参数、32768 词表、1024 训练位置、24 层、隐藏维度 768、12 个 Q 头与 6 个 K/V 头，每头维度 64。GQA 减少 K/V 投影头数，输入输出 embedding 共享权重。参数数来自实际模型统计，训练量来自消费位置计数，原始文本量则来自数据清单。见[实验摘要](../case_evidence/experiment_summary.json)。

### 实践步骤

demo 尝试读取本地训练配置，独立下载课程时会提示案例文件缺失。先从配置核对 batch=2、累积=8 和 block=1024，再算每步 16384 个位置。把设备信息、软件版本、训练峰值显存和吞吐作为另一组实测记录；目前这份摘要主要保存配置与质量结果，不能据它推断所有设备的速度。

### 检查与常见错误

课程的 0.2B 是参数规模近似说法，不是精确 200,000,000 个参数。12GB 显存不保证任意同参数模型可训练，长度、优化器、精度和算子都会影响需求。增加训练 token 不会自动增加模型参数，4B 扩展属于额外训练预算，不是更大架构。

答：参数量来自模型结构，训练 token 来自实际数据处理计数。
