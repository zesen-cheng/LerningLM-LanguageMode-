# 38｜案例：数据与 tokenizer

## 核心概念

本案例建立语料池、清洗/审计并训练 32K 词表。教学重点是来源可追溯、训练/验证隔离与 tokenizer 回编码测试，不把 2B token 自动称为高质量。

## 观察一个例子

按来源和类别记录保留率，比只报总量更能发现偏差。从原始语料抽出一份样本，记录来源与过滤原因；用新 tokenizer 编码、再解码，核对文本和 token 计数。随后检查训练与验证是否按文档隔离。

## 技术细节与实践流程

### 技术机制

实际流程从原始来源记录、机械清洗与 CCI4.0 评分，进入分位桶筛选、32K tokenizer 训练、编码检查和训练清单。本案例评分了 3,036,419 条机械清洗文档；入选训练清单含 1,999,984,673 tokens，验证部分为 22,234,771 tokens。高分净化池含验证约 2.215B，原定 10B 有效池尚无完整达成证据。

### 实践步骤

demo 提示在本地项目中检查数据与 tokenizer 产物；独立课程可阅读[实验摘要](../case_evidence/experiment_summary.json)和[完整复盘](../TRAINING_STORY.md)。核对 tokenizer 的 32768 词表与特殊 ID，再按清单追踪每个编码分片。本次固定六类样本回编码通过，联合抽检 288 篇；16K 对比的 19.45% token 减少只属于该验收样本。

### 检查与常见错误

高分不能自动改称“全是高质量人类对话”，抽样近重复检查也不能证明全量门槛达成。文档数、字符数和 token 数应同时保留各自口径。发现替换字符后删掉相关文档是具体修复，不代表其他语义质量问题已经被解决。

## 自问自答

**问：32K 指什么？**

答：约 32768 个 token ID 的词表规模。
