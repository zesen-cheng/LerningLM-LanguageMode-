# 39｜案例：预训练与基础评估

## 核心概念

将训练曲线与固定提示生成并看：损失改善证明预测目标在学习，但并不证明会多轮聊天。案例中出现人物接龙，应作为格式学习偏差分析。

## 观察一个例子

同一固定提示、同一采样参数下比较不同检查点。选一个早期和一个后期预训练检查点，用固定提示生成。若后期损失更低却仍生成“用户、大白、小白”接龙，就把它记为对话格式缺陷，而非忽略。

## 技术细节与实践流程

### 技术机制

预训练完成 122067 次更新，共处理 1,999,945,728 个位置，与清单 token 数因完整块消费等处理略有不同。固定基础评估使用 256 个长度 1024 的块，loss 从 60000 步的 3.6746 降到最终 3.3843，最终 PPL 约 29.50。这些数支持该验证分布上的预测改善，不是通用聊天成功率。

### 实践步骤

demo 查找本地基础评估报告；缺失时不生成虚构成绩。阅读[实验摘要](../case_evidence/experiment_summary.json)，再将 loss 与原始生成样本合看：10 个提示的贪心输出均触发退化检测，受控采样为 1/10。先对齐提示和参数，再检查事实、算术、角色与多轮表现，说明采样改进了什么。

### 检查与常见错误

不要用最终训练日志中较低 loss 代替固定验证结果，也不要把自动退化标记看成全面人工质量判定。人物接龙既与续写目标有关，也需要排查模板与结束配置；仅提高训练步数不能保证获得对话能力。
