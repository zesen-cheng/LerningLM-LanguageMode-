# 43｜结课：tokenizer 基线

## 核心概念

记录词表、特殊 token、未知片段处理、编码/解码一致性和各类文本压缩率。换 tokenizer 后不能直接沿用旧 embedding 权重。

## 观察一个例子

对中文、数字、英文混合样本分别计算每字 token 数。拿“今天 20°C，Python 3.12”做混合文本样本，查看特殊符号、数字与英文的 token 切分。训练前存下编码结果，换词表后重新比较长度与回编码。

## 技术细节与实践流程

### 技术机制

tokenizer 基线应固定词表、规范化、特殊 ID 和未知片段处理，并保存训练样本清单与产物哈希。测量中文、英文、数字、代码和混合文本的长度分布，报告 token/字符等指标时说明字符计数口径。一个词表在训练集上压缩好，仍可能在未见领域切得很碎。

### 实践步骤

demo 构造字符词表，做回编码并统计不同 bigram，用于建立最小基线，不会训练 32K BPE。进阶实验在相同训练样本上比较两种词表规模，在独立样本上做回编码与压缩验收。随后检查 token ID 范围、特殊标记和编码失败，再冻结 tokenizer 并生成训练分片。

### 检查与常见错误

tiny 演示的字符词表不支持所有未见字符，这一点不能隐藏。更换真实 tokenizer 后必须重新编码并匹配模型词表层；同样的 ID 数量并不保证语义对应。不要在测试结果不满意后不断调整词表，却仍将旧测试称为封存测试。

## 自问自答

**问：为什么词表越大不一定越好？**

答：模型 embedding 更大，且切分质量需靠真实分布检验。
