# 预训练｜解答与复习时间（35 分钟）

先做口头解释，再打开第 18–22 课演示和本项目训练配置核对。

1. **一次训练 step 是什么？** 通常指优化器更新一次参数，不是处理一条样本。若有梯度累积，多个 micro-batch 合成一个 step。`batch_size × 累积次数 × 序列长度` 给出每 step 处理的 token 位置数；真实有效 token 需扣除掩码/填充。
2. **epoch、训练 token、step 如何换算？** epoch 是遍历数据集一次；训练 token 是累计参与训练的位置量；step 是更新次数。重复采样或变长序列时不能只靠简单乘法，优先读日志计数。
3. **checkpoint 是什么？** 一次可恢复训练状态的快照，至少考虑权重、优化器、调度器、随机数状态、当前 step 与数据采样位置。用于推理的权重导出包通常比训练检查点小。
4. **KV 是什么？KV cache 呢？** K、V 是注意力中的键和值投影；自回归推理缓存已处理 token 的 K/V，避免每生成一个 token 就重算整个历史。它占显存，规模随上下文和并发增长；不是训练语料数据库。
5. **Dense 与“mov”是什么？** 常见术语是 **MoE（Mixture of Experts）**，而不是“mov”。Dense 模型每个 token 通常通过同一套 FFN 参数；MoE 用路由器选择部分专家参与。MoE 的总参数量与每 token 激活参数量要分开看。若“mov”指另一个具体架构，应以其官方定义为准。
6. **FFN 和注意力各做什么？** 注意力在位置之间汇集信息；FFN 在各位置上做非线性变换。两者都含可训练权重。
7. **FP64、FP32、TF32、FP16、BF16、FP8、FP6、FP4、INT16、INT8、INT4、NF4 有何区别？** FP64/FP32 是较高精度浮点；TF32 是部分 GPU 矩阵运算路径，不是常见模型文件格式；FP16 范围较窄，常配 loss scaling；BF16 指数范围接近 FP32、尾数精度较低；FP8 常有 E4M3/E5M2 变体并需缩放；FP6/FP4 位宽更小、通常依赖块级缩放与专门硬件；INT16/INT8/INT4 是整数表示，低位量化需尺度和零点等元数据；NF4 是非均匀 4 位量化格式，不等同于普通 INT4。MXFP8、NVFP4 又是带特定缩放约定的具体方案。精度、范围、显存与硬件支持要分别评估，不能仅按位数排序好坏。参见 [NVIDIA Transformer Engine 官方文档](https://docs.nvidia.com/deeplearning/transformer-engine/)和 [PyTorch 数值精度说明](https://docs.pytorch.org/docs/stable/notes/numerical_accuracy.html)。
8. **混合精度训练是什么？** 让部分矩阵计算使用较低精度，同时在关键累积或主权重等环节保留更稳定的表示；具体实现看框架/硬件，不能把所有张量一律改成 INT4。
9. **Scaling law 是什么？** 用经验关系研究模型参数量、数据量、计算量与平均损失的变化。它用于预算选择，不保证特定模型能聊天，也不替代数据质量与评估。参见 [Kaplan 等原论文](https://arxiv.org/abs/2001.08361)与 [Hoffmann 等计算最优训练论文](https://arxiv.org/abs/2203.15556)。
10. **学习率、warmup 和梯度裁剪各管什么？** 学习率决定更新幅度；warmup 在初期逐步提高学习率；梯度裁剪限制异常大梯度。三者解决不同问题。
11. **训练健康怎么看？** 一起看训练/验证损失、吞吐、梯度范数、数值异常、显存/温度、抽样生成与恢复测试。单条平滑 loss 曲线不足以证明语言质量。
12. **预训练数据质量如何证明？** 报告来源/许可、哈希、重复率、分层抽检、语言/主题覆盖、训练验证隔离和原始样例；自动质量分类器需要抽检校准。
13. **SGLang 是什么？** [SGLang 官方文档](https://docs.sglang.io/)将其定位为高性能语言及多模态模型推理服务框架；它解决部署和吞吐问题，不是 tokenizer 或 GPT 的必备训练算法。
14. **Jev 是什么？** 你给出的 [Jev 演示入口](https://jev-test-five.vercel.app/)对应 [TypeSafe AI 对 Jev 的官方介绍](https://typesafe.ai/blog/introducing-system-one-models-and-jev)：厂商将它描述为输入非结构化状态、输出预定义类型的概率决策的早期产品，而非逐 token 生成聊天文本的普通 GPT。厂商提到 RLCD，但未公开足以据此复现训练的完整架构/权重；其速度和能力主张应视为厂商报告，不能当成本课程复现实验结果。它也不是 JEPA。
15. **Jev 与本课为什么放在一起讨论？** 它帮助区分“语言续写模型”“结构化决策模型”和“推理服务框架”三个概念；本课程实际训练对象仍是自回归 GPT。
16. **Ollama、vLLM 与 SGLang 是什么？** 三者都是模型运行/服务相关工具，而不是本课的基础预训练算法。Ollama 重在易用的模型运行体验；vLLM 与 SGLang重在服务吞吐、延迟和并发；详细对比见[推理与网关复习](04_serving.md)。
17. **function calling 是预训练步骤吗？** 不是。它是部署阶段模型与宿主程序约定工具名/参数、由程序执行工具的交互机制；详细流程见[推理与网关复习](04_serving.md)。

## 自测与答案

- **题 A：** batch=2、累积=8、序列长=1024，单次更新的最大 token 位置数？**答：**16,384；有效训练 token 可能因掩码而少。
- **题 B：** 只保存模型权重后恢复，是否一定复现相同步数轨迹？**答：**不一定；优化器、随机状态与数据位置也会影响。
- **题 C：** MoE 总参数多，就必定比 Dense 每 token 计算量大吗？**答：**不必定；还要看激活专家数和路由/通信开销。
- **题 D：** Jev 能否直接替换你本地 GPT 的续写任务？**答：**不能据此假定；官方把它定位为结构化决策输出，而非自由文本生成。
