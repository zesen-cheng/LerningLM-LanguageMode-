# 推理与网关｜解答与复习时间（20 分钟）

本主题的核心是区分“训练出了权重”“能本地推理”“可由客户端稳定调用”三个不同成果。

1. **Ollama 是什么？** [Ollama 官方站点](https://ollama.com/)提供模型获取、运行与 API/工具链体验；是否本地、是否使用其云服务取决于实际配置。它不是训练算法。
2. **vLLM 是什么？** [vLLM 官方文档](https://docs.vllm.ai/en/stable/)将其定位于高吞吐推理与服务，包含批处理、缓存管理和兼容式接口等功能。它一般用于加载已有模型，而不是从零预训练框架。
3. **SGLang 与 vLLM 是竞争/替代关系吗？** 二者都可做推理服务，优化重点和支持矩阵会随版本变化；要用同一模型、硬件和请求分布测延迟、吞吐、显存，而不是只背框架名字。[SGLang 文档](https://docs.sglang.io/)。
4. **function calling 是什么？** 模型根据声明的工具模式返回工具名和参数；应用验证、执行并把结果送回模型。它不是模型自动获得电脑权限。参见 [OpenAI 官方 function calling 文档](https://developers.openai.com/api/docs/guides/function-calling)。
5. **结构化输出和工具调用有何不同？** 结构化输出约束返回格式；工具调用还需要实际的外部执行环节、错误处理与权限边界。一个合法 JSON 只是调用候选。
6. **HTTP/JSON、SSE 与网关分别是什么？** HTTP/JSON 定义请求响应；SSE 在 HTTP 上逐事件推送生成片段；网关做鉴权、路由、限流、日志和协议转换。三者是不同层。
7. **KV cache 在推理服务为何重要？** 它减少逐 token 生成的重复计算，但长上下文/高并发会增大内存占用。服务框架通常管理其布局和复用。
8. **量化部署意味着什么？** 用较低位宽与尺度表示权重以节省资源；实际速度和质量取决于模型、硬件、算子与校准，不可仅按文件大小比较。

## 自测与答案

- **题 A：** 模型输出 `{"tool":"search","query":"..."}`，搜索已经发生了吗？**答：**没有；宿主程序还需验证并执行。
- **题 B：** 手机上的 `127.0.0.1` 能直连电脑同名地址吗？**答：**不能；它指手机自己。远程访问需要另行设计网络路径和鉴权。
- **题 C：** 推理服务能跑通，是否证明训练流程可恢复？**答：**不能；训练检查点与推理导出是不同验证项。
